# JsonRepair.NET: Pre-1.0 Release Roadmap (0.x Hardening Tiers)

## Overview

`JsonRepair.NET` stays in the **0.x version range** (`0.1.0`, `0.2.0`, ...) until the library has
accumulated real-world usage feedback. This mirrors the release strategy of the upstream
`mangiucugna/json_repair` project (currently `0.61.x`), which matured entirely inside its 0.x line.

Each minor version delivers **one hardening tier**. GitHub Release notes serve as the migration
guide between minors. Phases 1–5 of the initial build-out are complete — see
[04-implementation-roadmap.md](04-implementation-roadmap.md).

---

## Versioning Policy

- **0.x.y minor**: may contain breaking API changes. Consumers should pin an exact minor
  (e.g. `Version="0.1.*"`) in production.
- **0.x.y patch**: bug fixes only, no API changes.
- **README status line** (to be added in 0.1.0):
  > **Status:** 0.x — the API may change between minor versions based on real-world feedback.
  > Pin an exact version in production. Report repair failures with a sample input via GitHub issues.

### 1.0.0 Gate Criteria

Promote to `1.0.0` only when **all** of the following hold:

1. Two or more consecutive minors with **no breaking API changes**.
2. Upstream test corpus (josdejong `index.test.ts` + mangiucugna cases) ported and green
   against **both** engines (string + UTF-8).
3. No open crash bugs and no known inputs where `Repair()` silently emits invalid JSON.
4. Evidence of real-world usage (issue tracker activity, reported edge cases resolved).

### Divergences accepted for 0.2.0

The two engines still differ in two narrow, opposite ways, both incompleteness rather than
fabrication, both recorded in [UPSTREAM.md](UPSTREAM.md):

- **UTF-8 more lenient:** trailing comma after a root primitive (`536,` → `536`), matching upstream.
- **String more lenient:** 6 `special-whitespace` corpus cases (NBSP, U+3000).

`Fuzz_BothEnginesShouldAgree` fails the build on any *other* disagreement.

## Deferred to Later Tiers (Upstream Gap Matrix — Summary)

Full analysis in the 2026-07-24 review. Not 0.1.0 scope:

- **Tier 2 (0.2.0):** ✅ delivered — valid-or-throw; upstream corpus port; fuzz/property tests;
  shared golden corpus across string + UTF-8 engines. Error positions moved to Tier 3.
- **Tier 3 (0.3.0):** input-relative error positions, ellipsis, unquoted values, missing colon/value, smart quotes, special
  whitespace, number normalization, invalid escapes, leading commas, unescaped-quote heuristics
  (`'it's'`), grammar-based key/value separation (eliminates literal-in-key bug class structurally).
- **Tier 4 (0.4.0):** escaped-JSON unwrapping, NDJSON, string concatenation, JSONP/MongoDB,
  strict mode, diagnostics report, redesigned converter.
- **Tier 5 (0.5.0+):** schema-guided repair, incremental/stream-stable repair, dotnet-tool CLI,
  HTML entities, `ensure_ascii` option, browser playground.

- Triage rule: every reported edge case becomes a corpus entry first (TDD), then a fix.
